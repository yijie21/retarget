How a single-image 3D model becomes a video tracker The exact mechanism behind “guided diffusion tracking” — turning SAM-3D (which only reconstructs an object from one picture) into a temporally consistent 6-DoF pose tracker, without any training. Grounded in the paper's equations and the real track_object.py command line.

The whole trick rests on one idea: a generative model doesn't just produce an answer — it produces it through a controllable trajectory (noise → sample). If you can gently steer that trajectory while it runs, you get new behavior for free. Here, the steering turns "guess the object" into "track the object."

1. The problem in one picture

Figure 1. SAM-3D is a single-image reconstructor. Calling it once per frame gives a different mesh each time — the object appears to morph (top). The fix: lock the shape at one anchor frame and let only the 6-DoF pose (position + rotation) vary across frames (bottom). That converts an instance-reconstruction model into a tracker.

But there's a catch: SAM-3D doesn't have a "pose-only" mode you can just call. Pose and shape come out together from one generative process. So how do you hold one fixed and move the other? That's where the generative trajectory and guidance come in.

2. Background: SAM-3D generates by flowing from noise

SAM-3D is a flow-matching model (a close cousin of diffusion). To produce an output it starts from pure random noise ε and integrates a learned velocity field vθ over a series of small steps until it lands on a realistic sample. Think of a particle released in fog, with the network telling it which way to drift at every instant until it reaches "a valid object."

Figure 2. Flow-matching generation = integrating a velocity field from noise to a sample over a handful of Euler steps. The pipeline uses 25 steps. Nothing here is trained at run time — the field vθ is the frozen pretrained SAM-3D.

3. The core trick: bend the flow toward what you already know

Normally each Euler step just follows vθ wherever it points. Guidance mixes in a second pull at every step — toward a reference you supply. The paper uses a simple convex blend (their Equation 1): take the model's own update, and lerp it toward the reference by a strength α.

shape channel xst = (1−αs)·( xst−Δ + Δ·vsθ )  +  αs·zsref(t)
pose channel xpt = (1−αp)·( xpt−Δ + Δ·vpθ )  +  αp·zpref(t)

with the reference "rails" being straight noise→target interpolants:  zsref(t) = (1−t)εs + t·x̄s (toward the frozen anchor shape x̄s)  and  zpref(t) = (1−t)εp + t·xpk−1 (toward the previous frame's pose xpk−1).

  • Shape: crank αs high → the sample is dragged onto the fixed anchor shape, so every frame reuses the same mesh. (This is the "lock the shape" knob — --guidance_strength 1 and --fix_scale_to_init_frame.)
  • Pose: set αp moderate → the pose is encouraged to stay near where the object was last frame, but is still free to follow the actual motion. (--pose_guidance_strength 0.5.)
Figure 3. Every Euler step is a tug-of-war: the frozen model's velocity vθ vs. a pull toward your reference zref, combined by α. No weights change — you're only routing the same pretrained flow. That's why it needs zero training.

4. Frame-to-frame: chaining the pose

The reference for the pose channel is literally the previous frame's answer. So tracking is a chain: solve frame k guided toward frame k−1, then frame k+1 guided toward k, and so on. This is what enforces temporal smoothness — the object can't teleport between frames.

Figure 4. The fixed anchor shape feeds every frame (dashed green); each frame's pose is guided toward the previous frame's pose (purple chain). A side input — the object's 2D rotational speed from TAPIR — modulates how strongly the chain pulls (next section). In the code this is --chain_poses --chain_on_diffusion.

5. Adaptive guidance: trust the past less when the object spins fast

A fixed pose-guidance strength is a trap. If αp is too high, a fast-rotating object lags behind ("over-rigidity"); too low, and a still object jitters or flips. The fix: make αp depend on how fast the object is actually rotating, measured cheaply in 2D by TAPIR point tracks. The paper's rule:

αp(k) = max( 0.1,   0.7 − 0.09·|Δθk| ) |Δθk| = in-plane rotation magnitude (from ~20 tracked points)
Figure 5. Adaptive pose-guidance schedule. When the object barely rotates, lean hard on the previous pose (stable). When it spins, release the guidance so the tracker can keep up. The rotation magnitude |Δθ| comes from tapir_velocity_tracking.py, which fits a rigid rotation to ~20 tracked points via SVD and writes motion_stats.json. (Exact constants 0.7 / 0.09 are from the paper; the qualitative high-rotation→low-α rule is the point.)
📂 Verified in code: scripts/tapir_velocity_tracking.py tracks the object mask with BootsTAPIR and "estimates translation + rotation velocity via SVD rigid fitting," saving per-frame rotation_vel to motion_stats.json. run_pipeline.sh then passes it straight in: track_object.py … --rotvel_json …/motion_stats.json.

6. Many guesses → pick the best (without likelihoods)

A generative model is stochastic — run it twice, get two slightly different poses. So per frame they draw 25 candidate poses and must choose. Computing each candidate's exact probability is far too slow, so they use a fast geometric procedure instead:

Figure 6. Per-frame selection: (1) sample 25 poses; (2) group them with a weighted SE(3) distance d = wt‖ti−tj‖ + wr·2·arccos|⟨qi,qj⟩| (translation + quaternion angle) and drop tiny clusters as noise; (3) render each surviving cluster's mesh and score its silhouette against the real object mask by IoU; (4) keep the best. Cheap, and no probability evaluation.
📂 Verified in the run command (run_pipeline.sh, stage 3): --num_pose_samples 25, --pose_selection cluster, --cluster_dist_thresh 0.3, --cluster_min_size 3 (drop clusters < 3), --cluster_w_rot 1.5 (the wr in the distance), --scoring_metric render_iou (the silhouette-IoU ranking). Matches the paper exactly.

7. The whole thing, as actually run

Here is the literal command the pipeline issues per object — every concept above maps to a flag:

python track_object.py \
  --init_frame  $n                # 🔒 anchor frame (shape fixed here)
  --fix_scale_to_init_frame       #    lock object scale to the anchor
  --guidance_strength 1           # α_s  — shape pulled onto anchor mesh
  --pose_guidance_strength 0.5    # α_p  — base pose-guidance strength
  --rotvel_json .../motion_stats.json   # adaptive α_p from TAPIR 2D rotation
  --chain_poses --chain_on_diffusion    # frame k guided toward frame k-1
  --euler_steps 25                # 25-step flow integration per frame
  --num_pose_samples 25           # 25 stochastic candidates / frame
  --pose_selection cluster        # SE(3) clustering ...
  --cluster_w_rot 1.5  --cluster_min_size 3  --cluster_dist_thresh 0.3
  --scoring_metric render_iou     # ... ranked by silhouette IoU vs mask
  --post_optimize                 # final pose polish
  --save_layout                   # write per-frame 6-DoF → layout.json

Why this answers your original question

Every step here is inference on a frozen pretrained model. The "guidance," the chaining, the adaptive αp, the 25-sample clustering — none of it has learnable weights or a loss. The large-scale training already happened (Meta's SAM-3D); this work only steers the sampler and post-selects. That's exactly how you get a temporally-consistent 6-DoF video tracker out of a single-image model without training anything.
